# Development status

AION is an unreleased local-development prototype undergoing security containment. Phase 1 intentionally disables remote control, remote screen access, arbitrary CLI execution, and update installation while secure replacements are designed. Owner-approved pairing now supports a narrow, tested host-to-host replication transport: two isolated AION hosts mutually authenticate through pinned TLS 1.3 certificates and exporter-bound Ed25519 proofs, then exchange bounded project-metadata ledger events with durable acknowledgements. This is not yet full synchronization: discovery, Tailscale routing, reconnect scheduling, working-folder replication and conflict-resolution UI remain incomplete. The intended product behavior is in [the master specification](AION_MASTER_SPEC.md); current verified status and gaps are in [the requirements traceability matrix](REQUIREMENTS_TRACEABILITY.md).

Documentation and screenshots must describe only verified behavior. See [the asset manifest](assets/ASSET_MANIFEST.md) for the release documentation gate.

A chunked file-transfer implementation exists in the working tree, but file access is disabled until handle-based filesystem containment is implemented and verified. Path-based checks cannot prevent a local process from replacing a directory between validation and a filesystem operation.

The workspace supports project rename, archive/restore, and Owner-authorized folder links as metadata; these links do not enable filesystem actions or sync. Ask and Plan can stream provider responses with cancellation, but live-provider behavior has not been verified with test credentials. An Owner may approve a bounded local SHA-256 operation on supplied text; it cannot access files, launch commands or contact the network. Task scope, results and checkpoints persist, and interrupted work is not retried automatically. General execution and file-sync access remain disabled.

An Owner-approved, one-time local Windows workstation lock request is implemented through a fixed, hidden, time-limited helper. Automated tests mock the OS call; an actual lock has not been verified. A dispatched request is reported as requested, not confirmed, and uncertain outcomes are not retried automatically.

The Home and navigation views now lead to the existing project and chat workflows, with separate Ask and device-target controls, a per-browser sidebar preference, and a mobile navigation bar. A Chromium test against an isolated real host exercises Owner enrollment, protected credential save/removal, project creation and folder linking, an approved text-hash task, a missing-provider error, and conversation recovery after reload. Other interface screenshots use synthetic API data and do not establish native WebView behavior. The new UI has not undergone full localization, accessibility, or native desktop validation.

For an isolated Windows development preview, double-click `scripts/preview/Launch-AION-Preview.vbs`. It builds into a new temporary directory and uses separate databases, vault, browser profile, instance identifier, and loopback port. First-run Owner enrollment is required. This is a development preview, not an installer or evidence of installed-app behavior. No real provider credentials are copied into it.

Native bootstrap has an unresolved local port-ownership race: the desktop shell treats any HTTP 200 responder on its configured loopback port as its daemon and may send that responder its per-launch bootstrap secret. A temporary preview port reduces accidental collisions but does not authenticate the listening process. Do not treat the preview as validated against local adversaries; bind bootstrap to the launched host identity before release.

Private-origin IPC work has verified bounded framed pipes and a separate real-WebView2 acceptance slice, but has not replaced the production shell. The existing bootstrap port-ownership race remains open. An isolated test reproduced legacy-origin key continuity and discovered an implicit favicon request that can bypass the test's initial interception; see [the slice report](PRIVATE_WEBVIEW_IPC_SLICE.md). Existing Owner migration and complete application integration have not been implemented.
